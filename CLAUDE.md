# Troon City: context for Claude

A SimCity-style city builder on Palo Alto's real terrain (the San Francisco Peninsula: Silicon Valley; until Nov 2026 it was Troon, Ayrshire), built in **Godot 4.7** (GDScript) by Sam, with a tech layer (companies, Tech zone, tech workers).
Read this first, then `GAME_DESIGN.md` (the full design) before changing gameplay.

## Working with Sam
- Sam is semi non-technical: explain in plain words, keep replies short and don't repeat yourself.
- In-game text: plain, short, British English.
- One feature at a time; Sam plays it in Godot and reports back. Commit after each working feature.
- Godot can't be run by Claude in the cloud, so changes there are untested until Sam plays them. On Sam's Mac, Godot may be available; if so, check with `godot --headless --path . --quit` (or `--check-only` on a script).

## Code rules (these have caused real bugs)
- **Strict typing.** Never infer with `:=` from a Variant (Dictionary/Array element, untyped function or `sim` member): write `var x: float = d["k"]`. Type loop variables: `for i: int in n`. Godot errors "Cannot infer the type" otherwise.
- **Shared enums must match**: `Tile`, `Growth` and `Overlay` are repeated across scripts with asserts in `game3d.gd`. `hud.gd` `OVERLAY_NAMES`/`OVERLAY_TIPS` line up with `world3d.gd` `Overlay` by index.
- All tuning numbers go in `settings.gd`.
- New saves must still load old ones: read new fields with defaults.
- Every model swap keeps the old boxes as a fallback: `if _models.has("name"): _add_model(...) else: <boxes>`.
- Syntax check: `gdparse <file>` (pip package `gdtoolkit`).
- **Dev tools never touch Sam's save.** Started with `--playtest`, `--shots`, `--examples` or `--promo`, the game's Save and Load use `game3d.DEV_SAVE_FILE` (`user://dev_tools_save.json`, via `game.save_file`), never `SAVE_FILE` (`user://troon_save.json`, Sam's city). Tests read `game.save_file`, never the path. The play test checks Sam's file is untouched at the end. (A play test once overwrote Sam's saved city, Nov 2026: it couldn't be recovered.) Never write to `user://troon_save.json` from a script.

## How things work (short)
- **Demand and happiness.** `happiness` (0–1) is built from parts: taxes vs services, services, leisure, rubbish, jobs, housing, power, water, pollution. `appeal() = 3 * happiness - 1` drives home demand: below 50% happiness nobody moves in, below 33% people leave. Shops and industry use `business_appeal()` (taxes, services, leisure, rubbish only). The `complaint_keys()`, `complaint_text()` and `complaint_fix()` wording is shared by the HUD, hover text and advisors.
- **Shops against offices** (rebalanced Nov 2026): `SHOP_JOBS_PER_PERSON` 0.16, visitors' shopping (stations, tourism, airport) summed and capped at `VISITOR_SHOP_MAX` (`sim.visitor_share`), `office_share()` adds tech workers on top (`OFFICE_SHARE_CAP`). The demand bars' hover is `hud.demand_text(sim)`: wanted people/jobs, `sim.demand_room()` (room by density) and plots needed (`plot_holds`).
- **Taxes** only hurt when services are poor (tax tolerance scales with service cover).
- **Growth.** Zones need a road (or bus cover), power, and water past the first stage. Districts: conservation caps height; the CBD allows skyscrapers (stages 7–8), which need transit cover.
- **Services, one at a time.** Cover is `coverage` (0-1 per service per tile, `_update_coverage`); `covered()` means at least `Settings.COVERED` (0.3). The rules per service live in simulation.gd: `service_matters` (who needs it), `service_holds_back` (held back right now: the phrase in `_zone_check`'s reason, `SERVICE_HELD_PHRASES`, the same ones advisors.gd's REASONS counts; fire: a built plot with no cover), `service_report` (the Services view's line), `service_reach` (a building's own cover, for its hover text), `service_gain` (what a new one would add, for the card while placing). The Services view's filter is a sub-mode, not more Overlay entries: `world.service_filter` (-1 all), painted by `_one_service_colour`, keyed by `_service_legend`, pins by `_update_pins`; HUD chips emit `service_filter_chosen`; game3d `_set_service_filter`, `_show_overlay_key`, `_auto_view` (Districts and Services tools switch view and go back), `_update_reach_preview` (the `reach_decal` Decal round the mouse). Tips carry `filter`. Map views are lit at `MAP_VIEW_TIME` in `set_time_of_day`; `world.clock_night` is the real night (the clock's speed uses it), `world.night` is 0 in map views.
- **Abandoned.** After 36 months in decline a plot may be boarded up. The instance colour alpha 0.5 tells the shaders (`COLOR.a < 0.75`) to draw it run-down.
- **Pollution** comes from industry, coal, gas, landfill and the harbour. Parks reduce it. It lowers land value and home growth, and has its own Pollution map view.
- **Traffic** (`_update_traffic` in simulation.gd, numbers under Traffic in settings.gd): car trips a day per road tile, worked out lazily (dirty each month and on any change, never saved). Homes send trips to work and the shops, split between groups of shops and works (squares, at most 16) by size and road distance; one road flood (BFS) per group, then each group's trips drain "downhill" along it, split evenly between equally short ways. About 20 ms for the demo town. **Congestion is view-only for now**: nothing reads it but the Traffic map view (`Overlay.TRAFFIC`, the last one; the road shader takes the colour via `overlay_on`), road hover text, the City panel, the advisors and traffic.gd. Hooks for later consequences: `traffic_at(i)`, `traffic_congestion_at(i)`, `traffic_band(i)`, `traffic_jammed_share()`. The play test checks that jams change nothing else (`_capacity_scale`, dev only).
- **Kinds of road.** Every road is still `Tile.ROAD`; its kind is `sim.road_kind[i]` (0 road, 1 avenue, 2 motorway; `Settings.ROAD_NAMES`, `ROAD_COSTS`, `ROAD_UPKEEPS`, `ROAD_CAPACITIES`, `ROAD_STEPS`), set with `sim.set_road(i, kind)` (`set_tile` makes a plain road) and saved as `road_kind` (old saves: all roads). The Road tool's kind is `_choice[Tool.ROAD]` (`_road_choice()`); menu ids `road`, `avenue`, `motorway`. Nothing opens onto a motorway: use `sim.is_street(i)` (not `tiles[i] == Tile.ROAD`) for anything about plots reaching a road (`_road_dist`, `_access`, `_plot_roads`, world3d `_frontage`). The traffic flood is weighted by `ROAD_STEPS` (one queue per kind, see `_update_traffic` step 2); capacity is per kind (`road_capacity(kind)`). Drawing: widths in `ROAD_HALF_WIDTHS` (world3d), the kind goes to road.gdshader in UV2.x (centre line flag + 2 x kind), which paints lanes, the middle strip and lamp light; wide roads are cut into strips across so they follow the ground; plots don't reach into the verge of an avenue or motorway (`_street_reach`). traffic.gd: `LANES`, `PAVEMENTS`, `KIND_SPEED`. Keep the widths and lane positions in step across world3d.gd, road.gdshader, traffic.gd and tools/make_menu_pictures.py.
- **Ground.** `_build_height_field` smooths the tiles into a height field 4x finer (12.5 m): the coast is a blurred land mask, so the shore is a curve, but every land tile's middle is kept dry and every sea tile's wet (gameplay stays tile based). The terrain is flat 800 m grid pieces lifted by `terrain.gdshader` from the `height_map` texture; `height_at()` reads the same samples, so anything placed with it sits on the ground. Never place things from `heights[]` (the raw tile heights). Beyond the map: mirrored hills, the coast carried straight on, then plain far land (`_build_far_land`) into the haze.
- **New tiles go on the end** of the `Tile` enum in all three scripts (after woodland: offices, the small services, airport, the landmarks), so old saves keep their numbers.
- **Services by tile**: never do `tile - Tile.POLICE`; use `sim.service_of(t)` (-1 if none) and `sim.service_small(t)`. `services[s]` counts big and small together, `small_services[s]` the small ones.
- **Airport** (`Tile.AIRPORT`, an "area" building): `_update_airports` (in `recount`) groups the tiles and `_lay_out_airport` gives each a role in `sim.airport_role` (AirportRole, +8 north-south runway, +16 runway ends and the taxiway by the stands). The shader paints runway, taxiway, apron and grass from the lot detail (`LOT_AIRPORT`, `airport()` in lots.gdshaderinc); world3d `_plan_airport` adds the terminal, tower, hangars and box airliners.
- **Landmarks**: `Settings.BUILDINGS` entries with `landmark`; `sim.tourism` is measured in `_measure_leisure`. One model each (`LANDMARKS` in world3d.gd, with a plain block as fallback). The Build menu has San Francisco's six (`Tile.PAINTED_LADIES`, `COIT_TOWER`, `FERRY_BUILDING`, `FINE_ARTS`, `TRANSAMERICA`, `SALESFORCE_TOWER`, on the end of the enum); the Painted Ladies are six `painted_lady` models in `PAINTED_LADIES` colours (`_plan_landmark`). The eight world ones (Big Ben...) stay in the enum and `LANDMARKS` for old cities, out of the menu.
- **Woodland** (Leisure, `Tile.WOODLAND`, the first tile added on the end): a `Settings.BUILDINGS` entry with `no_road` (`sim.needs_nothing()`: always working, no warnings). Its land value and pollution cleaning are summed round each tile and capped (`_sum_woodland`, `WOODLAND_*` in settings). Drawn by `_update_planted_woods` in world3d.gd like the natural woods (`_wood_kind`, `_clumps`, `_tree`), in the same 1 km squares (`_planted_nodes`, children of `woods`), refilled only near a change; each tree seeded by its spot. Its ground: `built_map` G (the terrain shader treats it as woods) and `LOT_WOODS` (road verges beside it).
- **Countryside.** Fields and hedges are drawn by the terrain shader from an integer hash (`field_at` / `frand`); `_field_at` / `_field_rand` in world3d.gd are exact copies used to plant hedgerow trees and conifer plantations, so keep the two in step. Woods, damp hollows and "near the sea" are per-tile values in `land_map`; `built_map` makes fields and wild ground give way where anything is built. Natural trees are grouped in 1 km squares, left out beyond `TREE_RANGE` camera distances (the shader paints a canopy there instead), and hidden per tile when built on.
- **Plot ground.** Every plot's ground (lawns and gardens, back courts, paving, yards, rough empty plots with a zone-coloured edge line, building-site earth, park layouts, school pitches, golf) is painted by `shaders/lots.gdshaderinc` (included by the terrain shader) from `lot_image`, one pixel per tile, filled by `_plan_lots`/`_write_lots` at the end of `refresh_buildings` (the bits are explained above `LOT_NONE` in world3d.gd). Plots reach into the verges of straight roads beside them, so a road tile's verges are painted as the plot next door's. The shader and the GDScript plans share layouts: use `_field_rand` (= shader `frand`) for per-plot choices both need (garden features, park layouts), and keep the numbers in step (e.g. `_park_open` mirrors the shader's park paths). Only things that stand up are instances (`_prop`, `_park_prop`, `_street_box`); flat slabs (`_slab`) get a texture from `shaders/paving.gdshader` by their colour (`_surface_of`). Empty zoned plots wait as rough grass (lines in the zone colour: one per density step) unless the town wants them (`growth_state` GROWING), when they're building sites with hoarding in the zone colour.
- **Rendering.** Box buildings use a MultiMesh with `INSTANCE_CUSTOM = (w, h, d, style)`. Models are stretched to each planned block and grouped into MultiMeshes per (model, 400 m chunk); each model's parts are joined into one surface at load (`_one_surface`: the part number is in UV2.x, so a model is one draw). Paving, props, parked cars and planted trees are filled with `_fill_chunked` (400 m squares as children of `paving`, `props`... so off-screen squares and shadow cascades skip them; `instance_total()` counts them). Never go back to one MultiMesh for the whole town: it was drawn in full by all four shadow cascades. `model.gdshader` picks its look per part by the .glb material name: stone, roof, glass, frame, door, metal, pot, fascia, render, awning, lead, cladding, sheet, accent, curtain (glass in the wall colour), display (shop windows), beacon (red aviation light), lamp (floodlit trim), office (office glass). Modern blocks and skyscrapers are stacked storey by storey.
- **Building colours are sRGB** (like props and paving): the building, roof and model shaders convert `COLOR` and the model's second colour to linear, except when a map overlay is on (overlay colours go in linear). Fixed colours written inside the shaders are linear. Writing building colours as if linear made everything pale.
- **Building looks are picked by position**, never at random per refresh: house colours come from a street palette (`HOUSE_PALETTES`, one per 3x3 tiles), tower designs and industrial kinds from the plot's own seeded `rng`.

## Example cities
- The game menu's **Example cities** (Village with the small services, Town with offices and the Painted Ladies, City with offices, an airport and San Francisco's six landmarks) load `examples/<id>.json` (`Settings.EXAMPLES`, `game3d._load_example`): ordinary save files, so they replace the city on the map like Load, and the player's own save is untouched until they press Save.
- `tools/make_examples.sh [picture dir] [--only=city]` rebuilds them (`scripts/dev_examples.gd`, which extends dev_shots.gd; `-- --examples=<dir>`): each is built with the real build tools from a fixed seed, grown with `sim.tick()` on topped-up money, then run two years on its own money (it must not lose money or people), saved, loaded back as a check, and pictured (default `screenshots/examples/`). About 4 minutes. Nothing is forced (no "showcase" step). The City is the screenshot town's plan plus a north suburb and terraces, a second works, more services, bus depots, three more roads to the works and woodland belts.
- **Rebuild them after changing the rules** (growth, money, services): they are snapshots, and the play test (`_examples`) checks each still makes money and is happy when loaded.
- Saves now also keep last month's budget (`last_income`...), read with defaults, so a loaded city shows its balance straight away.

## Building models and menu pictures
- Built headless with Blender's Python module (pip `bpy`; 5.1.2 was used with Python 3.13):
  `python tools/make_buildings.py assets/models [preview_dir]`. Set `ONLY=name1,name2` to rebuild just some models; the previews are worth looking at.
- Blender +Y is the street side, and becomes local −Z after glTF export. Each model function returns `(builder, (w, d, wall_h, roof_rise))`, which must match `MODEL_DIMS` in `world3d.gd`.
- Menu pictures: `python tools/make_menu_pictures.py assets/icons assets/textures item1,item2`. They use the same models and textures, so the menu matches the game. (Sam rejected menu art that differs from in-game looks.) Game colours are passed with `srgb=True` there, as the game's shaders treat them.
- A venv with bpy that works: `~/.venvs/troon-bpy` (Python 3.13, bpy 5.3). After exporting models, run `Godot --headless --path . --import` so the game sees them.
